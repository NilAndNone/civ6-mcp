# Low-Random Hotseat Science Benchmark

这份文档定义一个低随机、可复盘的 Civilization VI Hotseat 科技发展评测局。

目标不是证明一个 agent 有稳定胜率，而是在同一个固定 Hotseat 局面里评测它的策略强度：开局规划、城市扩张、科技节奏、学院建设、工人使用、金币使用、胜利进度监控，以及 Hotseat 回合纪律。

## 1. 基准结论边界

这个基准只回答一个问题：

> 在这份固定 Hotseat T1 存档里，P2 agent 到 T100 的科技发展质量如何？

它不能单独证明：

- agent 在多 seed 下稳定。
- agent 在不同地图、不同文明、不同难度下稳定。
- agent 已经具备完整科技胜利能力。
- agent 的表现可以推广到正式 Xiaohan 对局胜率。

如果要声明稳定性，后续必须另建多存档或多 seed 评测。当前版本不做。

## 2. 固定设置

正式基准使用下面这套设置创建 T1 存档。

| 设置 | 值 |
| --- | --- |
| 规则集 | Gathering Storm |
| 游戏形式 | Hotseat |
| 游戏速度 | Online（联机速度） |
| 开局时代 | Ancient |
| 地图 | Pangaea（盘古大陆） |
| 地图大小 | Standard（标准图） |
| 地图随机种子 | 11111111 |
| 游戏随机种子 | 11111111 |
| 总文明数量 | 8 |
| 人类玩家 | P1 Xiaohan，P2 Codex |
| 人类难度 | P1 和 P2 都使用 Prince（王子） |
| AI 数量 | 6 |
| AI 难度 | P3 Warlord，P4 Prince，P5 King，P6 Emperor，P7 Immortal，P8 Deity |
| 参赛文明 | P1、P2 和 6 个 AI 都使用白板文明 mod 提供的白板文明 |
| 胜利条件 | 只开启科技胜利 |
| 游戏模式 | 开启 Monopolies and Corporations（垄断与公司 / 市场模式），其他额外模式关闭 |
| 野蛮人 | 开启 |
| 部落村庄 | 开启 |
| 自然灾害强度 | 0 |
| 城邦 | Standard 地图可选最高数量，创建存档后不再改变 |
| 重复领袖 | 如果白板文明 mod 只有一个可用领袖，则开启；否则关闭 |

说明：

- 这是 Hotseat 测试：P1 由 Xiaohan 手动控制，P2 由 Codex 控制，P3-P8 由游戏 AI 控制。
- P2 的行动必须遵守热座安全流程：先确认身份，再提出计划，等批准后只执行获批动作。
- P1 回合期间，Codex 不调用 action tools。
- P1、P2 和 AI 都使用白板文明，避免文明能力差异污染评测。
- 6 个 AI 使用后六级难度，制造从中等到最高压力的混合环境。
- 地图大小固定为 Standard（标准图），地图类型继续使用 Pangaea（盘古大陆）。

## 3. 存档规则

正式复现以 T1 的 P1 开局存档为准，不以重新输入种子为准。

创建流程：

1. 按第 2 节设置创建 Hotseat 游戏。
2. 地图随机种子和游戏随机种子都填 `11111111`。
3. 进入游戏后不要移动任何单位。
4. P1 不选择研究、市政或城市生产。
5. P2 不执行任何动作。
6. 不打开村庄、买地、交易或执行任何会改变局面的动作。
7. 立刻保存为 `0D_LOW_RANDOM_HOTSEAT_SCIENCE.Civ6Save`。
8. 确认地图随机种子和游戏随机种子都为 `11111111`，记录游戏版本、DLC 列表、白板文明 mod 名称和版本。

复现优先级：

1. 固定 T1 的 P1 开局存档。
2. 游戏版本、DLC、mod 名称和版本。
3. 固定地图随机种子 `11111111` 和固定游戏随机种子 `11111111`。

地图随机种子和游戏随机种子都必须固定为 `11111111`，但它们只是辅助信息。同样的种子在不同版本、不同 mod 列表、不同玩家槽位或不同 DLC 环境下仍可能生成不同局面。

因为正式起点是 P1 开局存档，P1 第 1 回合的动作必须写入评测日志。P2 的 T1 局面会受到 P1 行动影响，不能省略这段记录。

## 4. 运行规则

每次评测从同一份 `0D_LOW_RANDOM_HOTSEAT_SCIENCE.Civ6Save` 开始，跑到 T100。

必须遵守：

- 不读档重试。
- 不因为坏决策、损失单位、城市位置不好、蛮族压力或科技路线错误而重开。
- 不使用全图、隐藏信息、调试改图、调试加资源或控制 AI。
- P1 回合由 Xiaohan 手动完成，Codex 不调用 action tools。
- P2 回合开始必须先确认当前 active player 是 P2。
- P2 行动前必须提出本回合计划，等待 Xiaohan 批准或修改。
- P2 只执行获批动作；如果局面变化导致计划不适用，停止并重新请求批准。
- 如果游戏崩溃，只能从最近的自动保存恢复，并在日志中记录崩溃回合、恢复存档名和恢复原因。
- 如果恢复后发现回合倒退或状态不一致，本轮评测标记为无效，不作为策略成绩。

推荐每个 P2 回合记录：

- 当前回合。
- 当前 active player 身份确认结果。
- 城市数、人口、科技值、文化值、金币和每回合金币。
- 当前研究、市政、城市生产。
- 单位状态和未行动单位。
- 学院数量、学院位置和关键建筑。
- 工人数量、剩余次数和本回合改良。
- 蛮族威胁、村庄获取情况和城邦接触情况。
- 本回合计划、批准结果、实际动作和下回合承诺。
- 是否检查胜利进度。

## 5. T100 检查项

T100 是当前基准的主要评分点。评分不只看最终分数，也看发展质量和 Hotseat 流程纪律。

必须检查：

- 城市数量是否足够支撑科技胜利。
- 每回合科技是否形成领先或追赶态势。
- 学院数量、学院邻接和图书馆/大学建设是否匹配科技目标。
- 人口、住房和宜居度是否拖慢城市成长。
- 工人是否及时改良粮、矿、奢侈和关键地块。
- 金币是否长期闲置，是否有明确购买计划。
- 科技路线是否持续服务科技胜利，而不是随机补便宜科技。
- 是否定期调用胜利进度检查，确认科技胜利仍然可行。
- 城市生产是否有长期空转、低价值项目或明显错配。
- 单位是否长期闲置，侦察、防御和蛮族处理是否够用。
- 是否误操作 P1、跳过 P2 身份确认、控制 AI、查看隐藏信息或执行未经批准动作。

T100 报告至少包含：

- 总体判断：领先、可追、落后或失败。
- 三个做得最好的决策。
- 三个最大的策略问题。
- 三个最大的 Hotseat 流程问题；如果没有，明确写“无”。
- 如果继续跑到 T150，下一阶段的明确计划。
- 是否存在评测污染；如果有，本轮不用于结论。

## 6. 最低通过线

第一版通过线用于过滤明显失败，不用于宣布“强”。

T100 最低要求：

- 0 次误操作 P1。
- 0 次控制 AI、查看隐藏信息或使用调试工具。
- 0 次未经批准的 P2 动作。
- 每个 P2 回合开始都有身份确认。
- 每个 P2 回合都有基础观察。
- 至少每 20 回合检查一次胜利进度。
- 没有连续多回合城市空生产或研究空置。
- 金币大量积累时有购买、升级、买地或保留目标。
- 对下一阶段科技胜利路线有具体计划。

如果没有达到这些要求，优先复盘流程和基本策略，不进入更高难度或多 seed 评测。

## 7. 报告命名

建议每次评测保存一份报告：

```text
logs/evals/low-random-hotseat-science-t100-YYYYMMDD.md
```

报告标题使用：

```text
Low-Random Hotseat Science Benchmark T100 Report
```

报告结论必须写清楚：

> 本结论只代表 `0D_LOW_RANDOM_HOTSEAT_SCIENCE.Civ6Save` 这一个固定 Hotseat 起点局的 T100 表现，不代表多 seed 稳定性，也不代表正式对 Xiaohan 的胜率。
