Codex HL Evolution Roadmap

这份页面是路线图的人类审阅版。长期权威来源仍是 docs/codex-hl-evolution-roadmap.md。

当前结论： v0.0.1 冻结入口、边界和本地验收； v0.0.2 验证 playbook 驱动的策略改进。

长期目标

codex-hl-civ6 的长期目标，是让 Codex 在真实 Civilization VI 对局里形成可审计的改进闭环：先完整记录，再标失败，再形成候选资产， 再用多场景验证，最后在 gate 通过时受控合并和回滚。

不做什么

  • 不把单个 test 1 结果当成通用策略结论。
  • 不让 Phase 1 判断策略好坏。
  • 不让候选 failure 直接变成资产改动。
  • 不跳过人工确认和 governance gate。
  • 不从 archive/legacy/ 恢复旧主线，除非用户明确批准。

三条主线

记录系统

记录系统回答：发生了什么，证据在哪里，结论能不能回到原始事实。 Phase 1 落盘工具调用、状态快照、决策记录和存档索引；后续阶段必须引用这些证据。

资产系统

资产系统回答：哪些 prompt、playbook、tool policy 和 memory 正在生效， 它们从哪里来，能不能回滚。Phase 4 只生成候选，Governance 才能在 gate 全过且显式允许时写资产。

验证系统

验证系统回答：改动是否真的更好，有没有退化。第一版主指标使用 T50： 城市数、科技、市政、科学产出和文化产出。

v0.0.1 和 v0.0.2

v0.0.1 是正式地基：文档结构、入口、边界和本地检查都清楚。 v0.0.2 是策略改进验证：自动从正式 failure 生成候选 playbook， 让 runner 直接读取候选 playbook，并在 Windows 真机上跑 5 baseline T50 + 5 candidate T50。

当前优先级

当前优先级是完成 v0.0.1 正式版本整理和审批。审批通过后再打 v0.0.1 标签。之后进入 v0.0.2，重点证明 playbook 驱动的策略改进。
