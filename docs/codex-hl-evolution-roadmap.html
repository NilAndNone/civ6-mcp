Roadmap: observation first, automation later
Roadmap v1

先记录真实对局，
再沉淀资产和验证集，最终自动合并。

这份路线图把系统拆成记录系统、资产系统、验证系统三条线。近期只做 Phase 1 观测，远期目标是不设人类 merge 闸门，由系统自动合并、自动回滚、自动审计。

当前优先级：Phase 1

先用真实 test 1 单人存档跑 3-5 回合，证明工具调用、回合状态、关键决策、存档关联都能完整落盘，再进入 T50。

阶段总览

Phase 0

边界和词汇

统一 episode、decision atom、asset、scenario、merge、rollback 等基础概念。

Phase 1

完整观测

记录一局真实对局。先短跑验收，再跑到 T50。此阶段不判断策略好坏。

Phase 2

失败标定

从真实 episode 中标出失败，保留证据，并归入六类能力维度。

Phase 3

资产体系

管理 prompt、playbook、tool policy、低信任 memory 的版本、来源、风险和回滚路径。

Phase 4

候选改进

从失败中提出候选资产改动，跑沙盒验证，产出证据包，但不做自动合并。

Phase 5

验证集沉淀

每次事故、退化、误判都变成 regression 场景，验证系统不再依赖单点证明。

L4

自动扩大验证

系统能根据风险自动增加验证场景和轮次，减少人工调度。

L5

自动合并和回滚

不设人类 merge 闸门。系统自动合并、退化时自动回滚，并生成审计报告。

三线并行演进

记录系统
Phase 0定义记录单位。
Phase 1落盘工具调用、状态、决策、存档关联。
Phase 2失败必须能回到证据。
Phase 3记录资产变化来源。
Phase 4记录候选改进链路。
Phase 5+退化样例可复现。
资产系统
Phase 0定义 prompt、playbook、tool policy、memory。
Phase 1只记录资产版本，不改资产。
Phase 2失败按六类能力归因。
Phase 3资产版本化、可回滚。
Phase 4生成候选资产改动。
Phase 5+满足条件后进入自动合并。
验证系统
Phase 0确定 T50 主指标。
Phase 1只产出指标，不宣称变强。
Phase 2真实失败变成回归样例。
Phase 3检查资产改动是否改善指标。
Phase 4沙盒验证候选改进。
Phase 5+多场景验证和退化检查。

六类能力主轴

planning

规划是否正确

目标、顺序、阶段判断是否合理。对应 playbook 和 prompt 中的规划规则。

execution

执行是否稳定

计划是否被正确执行，动作是否漏掉，执行顺序是否可靠。

memory/state

状态是否可信

是否误用旧信息、错记历史、忽略当前状态。memory 只能低信任参考。

tool grounding

工具证据是否足够

关键决策前是否查了该查的状态，是否误读工具结果。

verification

是否检查结果

执行后是否验证结果，是否把失败误判成成功。

recovery

失败后是否能恢复

出现错误后是否能补救、回滚、保留证据并进入回归样例。

自动 merge 的远期闭环

真实失败

来自 episode、事故、退化、误判。

候选改进

映射到 prompt、playbook、tool policy 或低信任 memory。

多场景验证

验证 T50 主指标，并检查明显副作用。

自动合并

三条线成熟后，不设人类 merge 闸门。

退化检测

发现后续表现变差或违反安全条件。

自动回滚

先回滚，再生成审计报告和退化样例。

自动 merge 不是近期目标。只有记录系统、资产系统、验证系统都成熟后，才进入 L5。

Phase 1 当前入口

Phase 1 合格标准

  • 全部工具调用和返回结果落盘。
  • 每回合状态快照落盘。
  • 关键决策前后的背景、候选动作、选择理由、执行结果落盘。
  • 存档文件和回合、决策、事件有关联。
  • 先跑 3-5 回合并产出 HTML 验收报告，通过后再跑 T50。

T50 第一版主指标

早期用 T50，因为它足够快，适合暴露问题和比较改动。

阶段细节

阶段 记录系统 资产系统 验证系统
Phase 0 定义 episode、turn snapshot、decision atom、save link。 定义 prompt、playbook、tool policy、低信任 memory。 定义 T50 和三项主指标。
Phase 1 完整记录真实对局，先短跑验收，再 T50。 只记录生效资产版本，不改资产。 只产出指标，不做策略好坏最终判断。
Phase 2 失败必须能回到具体证据。 失败按六类能力归因，不能映射的先保留。 真实失败开始沉淀成 regression 场景。
Phase 3 记录资产变化的证据来源。 资产有版本、来源、风险、适用范围、回滚路径。 检查资产改动是否改善 T50 主指标。
Phase 4 记录候选来源、改动、验证计划、结果。 生成候选资产改动，但不直接进主线。 沙盒验证候选改进，产出证据包。
Phase 5+ 事故和退化都能复现。 资产改动声明覆盖的能力维度。 多场景验证，退化样例进入验证集。
