# v0.0.1 正式版本说明

`v0.0.1` 是 `codex-hl-civ6` 的第一个正式版本。

这版的目标是把当前系统定成一个可理解、可检查、可继续迭代的起点。它正式
冻结入口、职责边界、证据产物、文档结构和本地验收方式。

## 本版本正式包含什么

### 基础观测与报告

- 真实 Civ6 Observation 观测入口。
- 已有 episode 的报告重建入口。
- 连接和环境诊断入口。

这些能力负责回答：真实对局里发生了什么，证据是否完整，报告是否能供人审阅。

### 离线资产与证据流程

- Review 离线失败标注。
- Strategy 资产库校验和 T50 只读比较。
- Strategy Candidate 候选改进包生成。
- Validation 被动回归场景登记。
- Governance 审计、显式合并和回滚入口。

这些能力正式纳入版本，但仍然保留职责边界：候选不是正式改动，审计不是自动
合并，人工确认和 gate 不能被跳过。

### 自动化编排待验入口

- `/civ6-runs` 纳入 `v0.0.1`。

它可以编排多局 T20/T50 和后续职责流程，但 `v0.0.1` 不把它描述成“已经证明
策略会变强”。策略改进验证放到 `v0.0.2`。

## 本版本不包含什么

- 不承诺候选 playbook 已经能稳定提升 T50 指标。
- 不承诺自动确认、自动迭代、自动合并已经完成真机策略改进验收。
- 不把单个 `test 1` 结果当成通用策略结论。
- 不把 `archive/legacy/` 重新纳入当前主线。
- 不提交默认本地产物 `episodes/`。

## 审批前检查

本地检查命令：

```bash
uv run codex-hl-civ6-strategy-assets --check
uv run python -m py_compile plugin/src/codex_hl/evidence/observation.py plugin/src/civ6_connector/server.py
uv run python -m py_compile plugin/src/codex_hl/review/failure_labeling.py plugin/src/codex_hl/strategy/registry.py
uv run python -m py_compile plugin/src/codex_hl/strategy/candidates.py plugin/src/codex_hl/validation/scenarios.py plugin/src/codex_hl/governance/gates.py
uv run python -m py_compile plugin/src/codex_hl/runs/orchestrator.py
uv run pytest tests -q
git diff --check
```

文档检查命令：

```bash
rg -n '"0\.1\.0"|v0\.1\.0' README.md docs plugin pyproject.toml plugin/.codex-plugin/plugin.json uv.lock
rg -n "自动化已证明|自动合并已验收|策略已变强" README.md docs plugin -g '!docs/v0.0.1-release.md'
```

期望结果：

- 资产库校验通过。
- Python 编译检查通过。
- 测试全部通过。
- 文档没有残留旧版本号。
- 文档没有把 `v0.0.1` 夸大成策略改进已验收。

## 审批通过后的打标步骤

审批前不要打 tag。审批通过后执行：

```bash
git add README.md docs plugin/README.md plugin/AGENTS.md plugin/commands plugin/skills/civ6-observation/SKILL.md plugin/.codex-plugin/plugin.json plugin/src/codex_hl/review/failure_labeling.py pyproject.toml uv.lock
git commit -m "docs: prepare v0.0.1 release"
git tag -a v0.0.1 -m "codex-hl-civ6 v0.0.1"
git push origin HEAD
git push origin v0.0.1
```

如果 `uv.lock` 没有变化，不要强行加入提交。

## 下一版目标

`v0.0.2` 是 Playbook 驱动的策略改进验证版。它要证明：

- 候选 playbook 自动来自正式 failure。
- 候选 playbook 真实影响 observation runner 的策略行为。
- Windows 真机完成 `5 baseline T50 + 5 candidate T50`。
- T50 主指标显示 candidate 相比 baseline 有改进，且没有明显退化。

详细目标见 `docs/v0.0.2-strategy-improvement.md`。
